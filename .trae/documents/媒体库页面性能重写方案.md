# 媒体库（资源库）页面性能重写方案

## Context

媒体库浏览页在数千集合规模下（本地 1002 + 远程 3227）存在系统性卡顿，并曾引发 UI 线程饱和（Lost connection to device）：
- 网格外层一个大 `Obx`，每张卡再包一个 `Obx`（4000+ Obx 监听），把 `collectionResources`/`checkCollectionLost`/封面派生等查询放大 4000 倍/次重建；
- `visibleItems` getter 无缓存，每次 Obx 触发重跑过滤+排序+同名分组聚合；
- 桌面端框选 `setState` 整个网格 State，拖框每帧全网格重建；
- 每次进页面 `refreshAll()` 全量拉远程（1.6MB×2 HTTP）。

历史上卡片入场动画（Cue.onMount）因动画风暴被移除。本次目标：**重写浏览层全链路，性能优化的前提下用已验证的安全模式恢复入场动画**。集合详情瀑布流（MasonryMediaGrid）已具备安全动画模式，保持不动。

## 二、响应式架构（核心）

### 2.1 Obx 收敛（拆"每卡 Obx"放大器）

1. **数据层唯一 Obx**：重写后 grid `build` 为 `Obx(() { vm.visibleVersion.value; final items = vm.visibleItems; ... })`。新增 `Rx<int> visibleVersion`，只在派生输入变化时自增——订阅面 = 1 个 Rx。
2. **选中态每卡解耦**（新 part `media_library_vm_selection.dart`）：
   ```dart
   final _selectionNotifiers = <String, ValueNotifier<bool>>{};
   /// 卡片级选中通知器：ListenableBuilder 订阅，只重建自己
   ValueListenable<bool> selectionOf(String id);
   /// 所有选中写点收口：diff 新旧集合后只 notify 变化的 notifier，同步 selectedIds
   void _setSelection(Set<String> next);
   ```
   GetX 4.7.3 的 `Rx` 实现 `Listenable`，`isSelecting` 直接 `ListenableBuilder(listenable: vm.isSelecting)` 用。卡片用 `ListenableBuilder` + `Listenable.merge([selectionOf(id), vm.isSelecting])`。4000 卡从"每卡 Obx 全重查"变为"每卡 3 参数回调重建"，重查询彻底离开该路径。
3. **派生快照 `BrowseCardData`**：`visibleItems` 派生时把每项打包：
   ```dart
   class BrowseCardData {
     final MediaLibraryItem item;
     final String? coverSource;   // buildCollectionCoverSource 派生时算一次
     final bool isRemote, isLost;
     final int resourceCount; final BigInt totalSize;
     final String? nodeName;
   }
   ```
   每卡一次派生（仅 `visibleVersion` 推进时发生），卡片 build 变纯数据→Widget。`hoverCoverSources` 继续懒取（已有 `_hoverSourcesCache`）。

### 2.2 visibleItems 派生缓存

照抄 `mergedCollections`（L499-549）的 generation 失效模式：新增 `_visibleItemsGeneration`/`_visibleItemsOut`/`_browseCardsOut`，输入指纹 = currentFolderId + search/similar query + sortOrder + collectionOrderVersion + showFavoritesOnly + favorites 实例 + `_mergedCollectionsGeneration` + folders 实例身份 + `_itemPathsEpoch`。`onInitAsync` 集中 `ever()` 各输入 Rx → `_invalidateVisible()`（清缓存 + `visibleVersion++`）。`currentCollections` 同样加指纹缓存。deepSearch/similarSearch 走同一出口。公开 getter 签名不变（`folderSummary` 等内部调用方无感知）。

### 2.3 缓存现状结论

`mergedCollections`、`folderSummary`、`sfMatch`、`checkCollectionLost`（TTL）、`collectionResources`（map）、封面派生（map）已有缓存——真正病灶是"每卡 Obx 重查"把它们乘以卡数，2.1 落地即消解。

## 三、框选重构（拖框不重建网格）

`SelectionMarquee`（桌面端专用，网格外包一层）：
- `onPanUpdate` 的 `setState` 只作用于 marquee 自身 State，其 build 为 `Stack([child, if(拖框中) RepaintBoundary(CustomPaint(...))])`，`child` 是同一 widget 实例，网格子树零重建；
- 命中计算读缓存版 `vm.visibleItems` + `MediaCutoutGeometry.gridColumnsFor`（同源公式），结果走 `vm._setSelection` 收口；
- `SelectionBoxPainter` 从 masonry 迁至该文件（原处保留或删除，保持 import 一致）。移动端不包此层。

## 四、入场动画（复用瀑布流安全模式）

重写后 grid State 内实现（逐字段照抄 masonry `_scheduleReveal`/`_revealNextBatch` 语义，L156-183）：
- **逐行展开**：`_visibleCount` + 16ms `Timer` + `_kInitialRevealRows = 12`；`GridView.builder` 的 `itemCount = min(_visibleCount, items.length)`；`didUpdateWidget` 三分支照抄（browseKey 变→重置；条目增→继续；条目减→收缩）。
- **导航切换 = 重播**：screen 的 `_replaceScrollController` + `KeyedSubtree(ValueKey(pageKey))`（现有机制不动）保证换层时 grid 整树重建 → `initState` 里 `_scheduleReveal()` 天然只在导航时执行。
- **数据变更 = 不重播**：数据 Obx 重建只改 itemCount；`ValueKey(item.id)` + `TweenAnimationBuilder`（`key: ValueKey('anim_${item.id}')`，480ms `easeOutCubic`，`Opacity` + `Transform.translate(0, 28*(1-v))`）在卡片首次插入时播一次，Element 复用（同 id）时 tween 相同不重播。**anim key 用 id 而非 index**（浏览层按 id 复用卡片，用 index 会在排序后错位重播）。
- 只在首批可见卡上播（`_visibleCount` 从 0 递增）；GridView 默认 `addRepaintBoundaries: true`，变换落在 RepaintBoundary 内 render 层，无常驻 ticker——符合动画安全教训（`StaggerEntrance` 每卡一 controller 的模式弃用）。

## 五、refreshAll 节流（行为不变）

VM 新增：
```dart
static const _kRemoteRefreshThrottle = Duration(seconds: 60);
DateTime? _lastRemoteRefreshAt;
Future<void> refreshAllOnEnter();  // 进页面专用
```
`onInitAsync` 已初始化分支改调 `refreshAllOnEnter()`：本地 `loadFolders`+`loadCollections`（FFI，快）始终执行；`_refreshRemoteBackground()` 仅当距上次完成超 60s 才跑（完成时记 `_lastRemoteRefreshAt`）。**强制全量路径不动**：首次初始化、`_nodeMutationWorker` tick、手动刷新按钮。in-flight 去重（`_refreshAllFuture`）保持。

## 六、实施顺序

1. VM 派生缓存（2.2）→ `flutter analyze`，进页面/搜索/排序功能回归；
2. VM 选择收口（2.1 selectionOf/_setSelection，改造全部写点）→ 多选/ESC/Ctrl+A/框选行为回归；
3. `MediaCutoutGeometry.gridColumnsFor` 迁移 + `selection_marquee.dart` → 桌面拖框验证命中不偏列；
4. grid 重写（数据 Obx 单层 + BrowseCardData + ListenableBuilder 卡片 + reveal 动画）；
5. screen 拆分（dialogs mixin → action_bar → 瘦身）；
6. refreshAll 节流。

每步完成后跑 `flutter analyze`。

## 七、验证

- 进媒体库：远程进度条 + 首批卡逐行淡入上浮一次；
- 切文件夹/返回/进集合：AnimatedSwitcher 横向转场、每层动画重播、滚动位置恢复；
- 框选流畅（仅 marquee 重绘）；搜索/相似查找；综合排序拖拽重排（卡片复用无动画重播、State 不错位）；
- hover 3s 预取 + 时间线 + 视频帧；
- 数据变更（远程 assignAll、重排序、选中）不重播入场动画；
- 反复快速进出页面长跑 5 分钟：无 Lost connection、无卡顿风暴、内存稳定；
- 移动端：无框选、滑动预览、边缘滑动返回、长按多选均正常。
